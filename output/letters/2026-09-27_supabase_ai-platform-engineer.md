## Cover letter

Your post says an agent that cannot be measured cannot be trusted with anything beyond reading, and that a dangerous action should have no code path at all rather than a warning label. I have built my agent work on the same rule.

web3-risk-mcp gives AI assistants six tools to check crypto wallets, tokens and contracts, and every one is read-only by design. Its scorer is rule-based and fully explainable, findings carry stable IDs, and decisive findings set a floor that trust signals cannot hide. Its HTTP layer caches, rate-limits and retries, so a failing source lowers confidence rather than breaking the run.

My compliance assistant has a golden suite of 50 labelled questions, a refusal rule enforced across prompt, guardrail and evaluation harness, and a check that strips any citation the model never retrieved. I evaluate retrieval and generation separately so a regression points to one part.

For durable state and audit, my ledger API on PostgreSQL requires an idempotency key on every write, uses a transactional outbox and never edits history: corrections are reversals, so any run can be rebuilt.

I have not been the only engineer on a platform before, but I have owned every project end to end. I work in UTC+1 and can start immediately. I would be glad to talk.
